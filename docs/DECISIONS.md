# DECISIONS

One line per decision: what and why.

- **No Docker daemon in the build sandbox**: PostgreSQL 16 is installed locally (service on :5432, databases `dienst` and `dienst_test`, role `dienst`). `docker-compose.yml` (db + MailHog) is provided for normal use; code only needs `DATABASE_URL`. Mail in dev goes to SMTP `localhost:1025` (MailHog) and is optional.
- **Dependency pins**: TypeScript 5.9, Vite 7, Vitest 3, ESLint 9, otplib 12, React Router 6, zod 4 (with fastify-type-provider-zod 6), Tailwind 4 (`@tailwindcss/vite`). Newer majors exist but these are the stable, known ones.
- **i18n keys are the German strings** (as in `design/i18n-de-en.json`); `de.json` is the identity map, `en.json` the translation. New keys are added in `extra.de.json` / `extra.en.json`.
- **Kysely types** are generated by `pnpm db:codegen` (`--date-parser string --numeric-parser number`); the pg type parsers in `apps/api/src/db/index.ts` match (DATE as `YYYY-MM-DD` string, NUMERIC as number). Bigint ids of `audit_log` stay strings.
- **Migration runner** applies `db/migrations/*.sql` in name order and records them in `schema_migrations`; `001_init.sql` is a verbatim copy of `db/schema_v1.sql`.
- **Workspace packages are consumed as TypeScript source** (no build step): `main`/`exports` point to `src/index.ts`; the API runs through `tsx`.
- **Pre-role token** (`preToken`, 10 min, `pre:true`) is returned by `POST /auth/login` when the user has several roles or must first set up TOTP; it is accepted only by `/auth/select-role` and `/auth/2fa/*`. Login also returns `displayName`, and `twoFactorSetupRequired`.
- **TOTP is enforced at role selection**: admin/super admin without `totp_enabled` can obtain a pre token but `select-role` for those roles fails with `FORBIDDEN_SCOPE` (`details.twoFactorSetupRequired`) until `/auth/2fa/verify` succeeds. TOTP secret encrypted with AES-256-GCM (`TOTP_ENC_KEY`).
- **Invitation / reset / activation-code hashes** are SHA-256 (not argon2) so the link token can be looked up by hash; the activation code additionally needs the username and is rate limited. Reset tokens reuse `invitation_token_hash` (1 h). The one-time link in invitation and reset mails is the only token ever mailed; it is never logged.
- **Account lock**: 5 wrong passwords lock the account for 15 minutes (`failed_login_count`, `locked_until`); responses stay a generic `UNAUTHENTICATED`.
- **Refresh token reuse** (presenting an already rotated token) revokes all refresh tokens of that user.
- **Scope layer** (`apps/api/src/lib/scope.ts`) is rebuilt from the database on every authenticated request (token claims `companyIds`/`hotelIds` are informational), so removing a role or hotel takes effect immediately. Super admin scope = all companies and hotels.
- **audit_log** is made append-only by a trigger (migration `002`) because a separate restricted DB role is not practical in a single-role dev setup; entries are hash-chained (advisory lock serialises inserts).
- **Seed admins have TOTP pre-enabled** with a fixed dev secret that is printed by `pnpm db:seed` (so e2e can log in); real setups go through the `/auth/2fa/setup` flow.
- **Migration 003** makes `employee.created_by_id`, `employee_contract.created_by_id`, `manager.created_by_id`, `import_job.admin_id` nullable: a super admin has no `admin` row, so NULL means "created by a super admin" (the audit log always names the actor).
- **GET /employees/:id for managers**: SPEC 5.4 lists AD/SA only, but 4.20 and 6.1 give managers a reduced list/detail; managers get the reduced/home-hotel view, never contact data or date of birth.
- **Authentication runs in Fastify `preValidation`** (before zod body validation), so an anonymous or wrong-role request gets 401/403 even with an invalid body.
- **`DELETE /kiosk-devices/:id` revokes** (status `revoked`) instead of deleting: punch records reference the device row.
- **Seed**: contracts of the 15 sample employees start on the seed date and the sample "Zeitkonto" is stored as `opening_balance_hours`, so the computed time account equals the prototype value on seed day; "Resturlaub" is stored as allocated days (+ carry-over in `carried_contractual_days`). Demo PINs, the demo password (`Demo!2345`), the kiosk token and the admin TOTP secret are fixed so the printed output and the e2e suite are reproducible. `pnpm db:seed` always wipes the database (refuses in production).
- **Time account** also credits public holidays (resolved for the home hotel) that fall on working weekdays without an absence or punch, for salary workers (SPEC 4.15 "public_holiday").
- **Setup checklist "rules viewed"** is stored as an audit row (`rules_viewed`) per company instead of a new table.
- **Extra endpoint** `GET /setup/overview` (KPIs, action needed, recent changes) feeds the admin overview; not in SPEC 5.9 but required by DESIGN 4.5.
- **Employee create** accepts optional `openingBalanceHours`, `isFloater`, `phone`, `preferredLanguage` (additive to SPEC 5.4).
- **Seed shift breaks follow SPEC 7** (30 min for shifts longer than 6 h 30, none for Frühstück 06-11), so Frühstück is 5 h paid, not the 4.5 h of the prototype's sample data.
- **Staffing PUT** replaces all weekday defaults and date overrides of a shift; a weekday without a row means "no requirement". Seed requirements: Frankfurt Rezeption Früh/Spät/Nacht 1 each Mo-Fr (Sa-So Früh 1), Housekeeping Tag 3 (weekend 1), Frühstück 1; Berlin Rezeption Früh/Spät 1 each (weekend Früh 1), Housekeeping 2 (weekend 1), Frühstück 1. The per-department sums equal the prototype's "min." values (weekends halved as in the prototype).
- **Split shifts and rest periods**: entries on the same hotel-local start date are one working day (split shift): they count together for DAILY_LIMIT / MINOR_DAILY but are not neighbours for REST_PERIOD / MINOR_REST. Rest checks look at the nearest entries on other days, across all hotels.
- **PERIOD_CLOSED** appears as a violation code in `/schedule/validate` (status `blocked`) and as HTTP 409 `PERIOD_CLOSED` (with the violation in `details`) on writes (SPEC 4.3 vs 4.11 reconciled).
- **needs_reason / REASON_REQUIRED**: a write whose aggregate is `needs_reason` without a valid `overrideReason` (5-300 chars) returns 422 `REASON_REQUIRED` with the violations; with a reason it succeeds and writes a `rule_override` audit row listing the codes. An `emergencyOverride` by AD/SA downgrades only DAILY_LIMIT, MINOR_REST, REST_PERIOD to needs_reason; managers' flag is ignored.
- **Explicit start/end win over a shift template** on create/update (so planners can adjust times of a template entry); the template still supplies department and default break.
- **Absence rules**: any approved absence (including a free day) blocks work entries (`ABSENCE_CONFLICT`); a new absence replaces overlapping *free-day* markers (carved out) but is blocked by any other overlapping absence (`ABSENCE_OVERLAP`, 422). Deleting an absence sets it to `cancelled`, restores the allowance and un-cancels the entries it cancelled unless something else now occupies the time.
- **Notifications on schedule changes**: editing/moving/deleting a published entry creates a `schedule_changed` notice immediately (SPEC 4.10); publishing notifies `schedule_published` (new-only) or `schedule_changed` (any changed/removed) and skips entries that already produced a live notice since the previous snapshot (SPEC 4.18 without double notices).
- **Publish operates on whole ISO weeks** intersecting `from..to` and writes one snapshot per hotel and week; `changedCount` = new+changed+removed items published, `openSlots` = sum of open slots over those weeks.
- **Swap** exchanges the (employee, date) slots of the two entries; each keeps its own time of day. Implemented by parking one entry 100 years ahead inside the transaction because the exclusion constraint is not deferrable.
- **Grid** extras: `days[].past/closedHotelIds`, per-cell `locked` ('past'|'closed'), rows carry `reduced`, `isMinor`, `isFloater`, `homeHotel`, `isOtherHotel`; other-hotel entries of listed employees are returned as read-only markers (`isOtherHotel`, `otherHotelName`); `counts.openRequests` counts pending absences/corrections/worked-time records; week status is `published` only when no drafts and no changes against the latest snapshots exist.
- **Seed schedule** follows the prototype letter patterns for the ISO week of the seed date (published) and the next week (published Mon-Thu, drafts Fri-Sun); `F` becomes a free-day absence, `U` an approved vacation (current week) or the pending request (next week), `S` Berufsschule, `K` sick leave (current week), `X` an early shift at Berlin for the floater.
- **Planning UI**: the Abteilungen filter groups departments by name across hotels (the API takes `departmentIds`); week range only; the palette also offers "Frei" (free day absence); a drop is validated with `POST /schedule/validate` while dragging (green / amber / red / grey while pending); Alt at pick-up or during the drag turns a move into a copy; dropping on a chip swaps. Keyboard path: arrow keys move between cells, `+`/Insert/Enter opens the cell menu, Shift+Arrow selects a day range, Delete removes the focused entry, and the side panel offers employee/date move fields as the keyboard alternative to dragging.
- **Warnings are not computed for past days** in the grid (past days are locked); a blocked drop by an admin whose violations are all overridable offers the emergency exception dialog (reason required, audited).
- **`GET /schedule/candidates?includeBlocked=true`** returns blocked employees flagged `blocked` so the + menu of the shift view can grey them out with the reason (additive to SPEC 4.17).
- **E2E suite** lives in `e2e/` (own workspace package); `pnpm e2e` re-runs `db:migrate` + `db:seed` first and reuses a running API/web dev server or starts them.
- **Kiosk**: `employeeRef` and `confirmToken` are HS256 JWTs (5 min) signed with `JWT_SECRET`, bound to the device (and employee / record). The tablet stores its device token in `localStorage` (`kioskToken`); an unknown or revoked token shows the "Gerät nicht registriert" screen with a token field. Clock-in with an open record younger than 60 s returns the same record (idempotent), older answers 409 `ALREADY_CLOCKED_IN`. Break options are `[0,15,30,45,60]` plus the required value when it is not in the list; the suggested value is the larger of planned and required break. The roster also returns `hotelName`, `deviceName`, `pinLength` (additive).
- **Gross minutes for the break rule** are measured on the paid window (paid start to paid end after the grace logic), not on raw presence.
- **PIN lock**: the 5th wrong PIN answers 423 `PIN_LOCKED` (the 1st-4th answer 401 `PIN_INVALID` with `remainingAttempts`); an expired lock resets the counter.
- **Auto-checkout** runs every minute inside the API process (`buildApp({autoCheckout:true})`, enabled by `server.ts`); tests call `runAutoCheckout(db, clock)` directly. Records stay `source='kiosk'` with `auto_checked_out=true`.
- **Live**: records needing review are listed only under "Prüfung nötig" (not also under "Eingestempelt"); expected/no-show consider published entries of the hotel-local today without a non-rejected time record.
- **Seed punches**: today's started published entries get approved closed punches (or one open punch), plus an open unplanned punch for Piotr, Sven's auto-checked-out Wednesday with a pending missed-clock-out correction and Maria's late Tuesday with a pending wrong-time correction.
- **Pending vacation requests** (inbox) are `annual_leave` rows with `status='pending'` created by the employee's own user; planner-entered absences are never pending.
- **Bulk approve** runs one transaction per record so one flagged or closed record never blocks the rest; flagged records come back in `failed` with the flags.
- **`GET /approvals/count`** (extra, read-only) feeds the inbox badge; it counts finished pending records, pending corrections and pending vacation requests of the caller's hotels.
- **Corrections** are also refused at request time when the day lies in a closed period (SPEC 4.7 only names approval); the decision re-checks it.
- **Vacation requests** may not start in the past (422-free `VALIDATION` 400) and may not overlap a pending/approved absence (409).
- **Period close** treats open punches (no clock-out) in the range like pending approvals (`PENDING_APPROVALS`, `open: true`); overlapping an already closed range is 409 `CONFLICT`.
- **Audit log** visibility: super admin sees everything, an admin only rows of their companies (rows without a company, e.g. logins, are super-admin only). CSV export is capped at 10 000 rows.
- **Regeln tab** shows static text of the built-in rules; opening it calls `POST /setup/rules-viewed` for the onboarding checklist.
- **E2E**: the test API runs with `RATE_LIMIT_AUTH=1000` (many logins from one IP) and the helper waits for a fresh TOTP window because the server rejects replayed codes.
- **Timesheets** (planner `GET /timesheets`, employee `GET /me/timesheet`) list approved records only and state how many unapproved ones are left out; absences come from approved `time_off`. PDF is German (pdfkit, built-in Helvetica), Excel via exceljs.
- **Schedule export** is built from the grid result (same scope, same filters), so it shows exactly the grid; the PDF stays the browser print view (SPEC 5.4).
- **Extra endpoint** `GET /me/time-off-requests/preview` returns day count and remaining allowance so the portal never counts days itself.
- **Portal times** in correction requests are entered in Europe/Berlin (the browser converts to UTC); hotels in other time zones are not a v1 case.
- **Migration 004** adds result columns to `import_job` (`created_by_user_id`, `file_name`, `result`, `raw_rows`, `credentials_enc`, `credentials_expires_at`, `credentials_downloaded_at`) so super admins (no `admin` row) can import and the per-row result, error rows and the credentials sheet survive the request.
- **Import semantics**: one transaction per upload with a savepoint per row; invalid rows are reported and skipped, the valid rows are committed (a system error rolls everything back). `dryRun=true` runs the same code and rolls back. `onDuplicateEmail` applies to an existing employee with that e-mail in the company: `skip` (reported as skipped), `update` (first name, last name, date of birth), `conflict` (reported as an error). A repeated e-mail inside the file is an error (`DUPLICATE_IN_FILE`). Hotel and department columns are ids (the template's "Hinweise" sheet lists them for the caller's scope).
- **Credentials sheet**: PINs and activation codes of an import are stored AES-GCM encrypted (same key as TOTP), downloadable once within 24 h (409 afterwards), wiped on download and by the minute job after 24 h. Import jobs are visible to their creator and super admins only.
- **Import limits**: `.xlsx` only (`.xlsm`, macro workbooks and non-zip files are rejected with 400), 10 MB (413 `PAYLOAD_TOO_LARGE`), 5000 data rows (413). Hashing a PIN per created row dominates the run time (about 0.1 s per row).
- **Hardening**: a global rate limit (`RATE_LIMIT_GLOBAL`, 600/min and client, `/health` exempt) next to the auth and kiosk limits; `trustProxy` is now opt-in (`TRUST_PROXY`) because trusting X-Forwarded-For unconditionally lets clients dodge rate limits; production refuses the development secrets and insecure cookies.
- **Kiosk fix**: a name found by search now asks `/kiosk/punch-status`, so an employee who clocked in unplanned can clock out through the search path (before, only roster cards offered the clock-out).
- **Backlog scope (owner decision)**: SPEC §10 is built except biometrics, GPS, employee sick reporting and wage/hourly-rate fields; SSO is generic OIDC, the "public API" is read-only with API keys, native apps are replaced by an installable PWA.
- **Migration 005** adds `absence_blackout`, `employee_shift_wish`, `employee_leave_wish` (with decision columns) and `vacation_notice` (unique per employee, year and kind).
- **Blackouts**: approved absences of other employees in the same primary department count towards `maxConcurrentAbsent`; pending requests do not. Employees are blocked, planners need a reason (audited `rule_override`).
- **Half day**: only annual leave on one day; allowance moves by 0.5; a half day never cancels entries (`PlanEnv` ignores half-day absences for `ABSENCE_CONFLICT`).
- **Wishes** only warn (`WISH_CONFLICT`); declined and withdrawn wishes no longer warn. Granting is a status, not a schedule entry.
- **Carryover** sets (not adds) the next year's carried days from the unused remainder (statutory days first) and is idempotent; expiry is a job on 1 April that only touches employees with a notice for the previous year, because without proof of information the days do not expire.
- **Migration 006**: manual ledger lines (`arbeitszeitkonto_entry`, only `correction` and `payout`), `hour_category`, `punch_record_category_minutes` (reserved for a period-close snapshot; the export computes live), `rule_profile` (+ `company.rule_profile_id`, `hotel.rule_profile_id`), `company_feature`. The cached `arbeitszeitkonto` table is not created: the balance is always derived.
- **Ledger granularity is monthly** because the v1 target is pro-rated per calendar month; a daily ledger would not reproduce the reference balance. Line sums may differ from the balance by rounding (< 0.05 h).
- **System hour categories are code, not rows** so a database reset cannot remove them; company rows override by code.
- **Break minutes are deducted from category minutes only when `break_segments` were recorded**; otherwise categories use the paid window as is.
- **Rule profiles can only tighten** the statutory limits (also for collective agreements) because the engine must never allow less protection than the law; the daily and rest rules read the profile, minors keep their stricter floor.
- **Rest compensation and replacement rest days are computed from the planned schedule** and reported, not blocked; the 10 h rest block and the emergency override of v1 stay as they are.
- **`openSlots` in analytics** sums required headcount minus assigned entries per shift and day over at most 62 days.
- **Absence "More" menu**: all seven extra types are accepted by `POST /schedule/absence`; `comp_time` additionally requires a time account.
- **Migration 007**: swaps, open shifts, qualifications (+ `shift.required_qualification_id`), availability, documents (`content_enc`, `mime`, `file_name`, `size_bytes` added to the reference table), announcements, questions, feed, calendar feed, `employee.terminated_at/termination_reason`.
- **Planning operations are shared** (`services/planning/run.ts`): swaps, open-shift approvals and the auto-approval run the same `update`, `swap` and `create` operations as the planner UI, so every rule check, notification and audit row stays identical. The auto-approval uses a company-wide system planner identity and is never exposed to clients.
- **Swap eligibility**: blocking violations refuse a request; `needs_reason` and warnings go to the approving planner, who can approve with an override reason.
- **Open shift approval creates a draft entry** (the planner publishes as usual) and notifies the employee at once.
- **Manager scope by department (`manager_department`) is not built**: it would change the one scope layer and every query; managers keep hotel scope.
- **Employee documents** are limited to the six non-health types; a diagnosis or sick note type is deliberately not offered. Files are identified by their content, not the file name.
- **Feed and announcements are plain text**; there is no HTML or link rendering, so nothing can inject markup.
- **Offboarding does not anonymise** employee data: retention (`company.retention_months`) and anonymisation jobs remain a policy decision; the exit statement and the deactivation are built.
- **Calendar feed**: the ICS shows shifts and "Abwesend" days only (never types or reasons) and refuses inactive employees or a disabled feature.
- **Notification reminders** (qualification, document, contract end) use a payload key per subject and threshold so a repeat run never duplicates them.
- **M13 offline PINs**: the PIN cannot be verified offline without caching verifiers, so a queued punch stores the PIN encrypted (AES-GCM, non-extractable key in IndexedDB) and the server verifies it on sync. A wrong PIN is rejected and the planners are told; every offline punch needs manual review, which bounds guessing. No PIN verifier is ever cached.
- **M13 offline roster** lists only people with a shift within 24 h or an open record; others cannot punch offline (the tablet falls back to "no connection").
- **M13 break segments**: a segment shorter than 15 minutes is stored but does not count (ArbZG § 4: breaks of at least 15 minutes). The clock-out confirmation remains so the employee can correct the total.
- **M13 web punch** needs a non-empty network list; an empty list never matches (safe default). Requests behind a proxy need `TRUST_PROXY` for the right client IP.
- **M13 public API** never names health-related absence types; `time_off.type` is mapped to `vacation` or `absence`. Keys are read-only by construction (GET routes only).
- **M13 SSO**: an admin-supplied issuer URL is fetched by the server (https required in production); there is no private-address filter, so only trusted admins should configure it. SSO administrators need IdP MFA; because the local TOTP check is skipped for them, `switch-role` back to admin after an SSO login needs a new SSO login or a local TOTP. Super admins are excluded from SSO.
- **M13 SSO ticket**: the web app gets a 2-minute single-use ticket in the URL fragment (never sent to a server log) instead of a session cookie set during the cross-site redirect. `requirePreOrAccess` now rejects any signed payload that is neither a session nor a pre-token.
- **M13 staffing suggestions** are applied as date overrides of `shift_staffing_requirement`, never as schedule entries.
- **Security dependency update**: nodemailer 10, react-router-dom 7, vitest 4, and a `uuid` override (^11.1.1, via exceljs). The one remaining advisory (`braces` through `kysely-codegen`, no fixed version) is a dev tool that only globs fixed paths, so it is accepted; CI audits production dependencies and fails on moderate or higher.
- **Security headers**: the API sends a deny-all CSP, nosniff, no framing, no referrer, a locked permissions policy, HSTS only in production and `no-store` by default; CORS allows exactly `WEB_ORIGIN` (other origins get no CORS headers). The web app's header list lives in `apps/web/security-headers.ts` and is applied to `vite preview`, written to `dist/_headers`, and documented for nginx in `docs/DEPLOYMENT.md`. The dev server stays without CSP because hot reload needs inline scripts. `style-src` keeps `'unsafe-inline'` because the UI uses React `style` props; scripts never run inline. The CSP was checked by loading planner, portal and kiosk pages from the production build with no violations.
- **Key separation**: signing and data keys are derived with HKDF-SHA256 per purpose from `JWT_SECRET` and the new `DATA_KEY` (`lib/keys.ts`); the raw `TOTP_ENC_KEY` is a read-only legacy fallback. Existing ciphertexts keep their layout (iv | tag | data); the right key is found by GCM authentication, so no format flag or migration is needed to read old data, and `pnpm security:rekey` moves it to the current key. Badge hashes are looked up under every configured key and upgraded on first use (the badge itself is not stored). Old session tokens stop working once (users sign in again). Rotation uses `JWT_SECRET_PREVIOUS` / `DATA_KEY_PREVIOUS`. Asymmetric JWTs and a key id in the ciphertext (for fast key lookup) are possible later steps.
- **Outbound request guard** (`lib/ssrf.ts`): everything the server fetches from an administrator-supplied URL (SSO discovery, token endpoint, signing keys) goes through `safeRequest`: https only, no credentials, internal names and literals refused, the resolved addresses checked at connect time (private, loopback, link-local/metadata, CGNAT, multicast, documentation, IPv6 ULA and embedded IPv4 are blocked), no redirects, 1 MB and 5 s limits. Signing keys are fetched through the same guard and used as a local key set. Private addresses are allowed only outside production or with an explicit `OUTBOUND_ALLOW_PRIVATE=true` (identity provider inside the same network).
- **Client address / proxies**: `TRUST_PROXY` is `false` (default), a hop count N (the N nearest hops are our proxies, the next address is the client) or a list of proxy addresses/CIDRs; `true` (believe every hop, so a client can forge its address) is refused in production. The hop count is implemented as an explicit function because Fastify's own number option counts one hop differently (found by test). Without a trusted proxy the web punch check fails closed and the API warns once about an unused `X-Forwarded-For`. Web punch audit entries carry the client address.
- **API key limits** (migration 009): every key expires (at most 2 years, default 1 year; keys that existed get one year from their creation), carries scopes (`hotels|employees|schedule|attendance|absences:read`, at least one, chosen at creation) and can be limited to network ranges; the last used address is stored. Expiry reminders (14 and 3 days) go to the creator and the company admins through the daily reminder job. Rotation is "create a new key, revoke the old one"; there is no in-place renewal so a leaked key can never be extended.
- **Cookies**: over https (`COOKIE_SECURE=true`) the refresh cookie is `__Secure-rt` and the SSO state cookie `__Secure-sso_tx` (the browser refuses them unless set securely); plain names stay for http development. `__Host-` was not used because it needs `Path=/`, and these cookies are limited to their API paths on purpose. The refresh cookie is now `SameSite=Strict` (only the web app's own requests need it); the SSO state cookie stays `Lax` because the identity provider returns the browser with a cross-site navigation. Cookies from before the prefix are still accepted over https for one rotation and then replaced and cleared, so nobody is signed out by the upgrade.
- **Audit chains per company** (migration 010): `chain_key` (company id, or one of 16 negative sub-chains for entries without a company), `prev_hash`, `hash_version`. The hash now covers only stored values (including `created_at`, which is set by the app) in a canonical JSON form, so `GET /audit-log/verify` (admins: own company; super admin: all) can recompute it; the old scheme hashed a timestamp that was never stored. Rows written before the migration stay version 1 and are reported as not verifiable; each new chain starts fresh. Keep the `head` hash of a chain elsewhere to also detect removed tail rows. `audit()` on a plain connection now opens its own transaction (the lock lives as long as the transaction; without it two writers could fork a chain).
- **Indexes** (migration 011) come from measured queries on synthetic data (`scripts/perf`, `docs/PERFORMANCE.md`).
- **Operations**: the API is bundled with esbuild into `apps/api/dist` (workspace packages inlined, other dependencies installed with `pnpm deploy --prod`), so the image has no TypeScript runtime and starts as `node server.mjs`. The migration CLI is its own entry (`migrate-cli`) because a bundled module must not run migrations when imported. Migrations hold an advisory lock; `.down.sql` files exist for 005 to 011 and a test proves up, down, up gives the same schema (001 to 004 cannot be rolled back). Liveness never touches the database (an outage must not restart healthy processes); readiness checks database, migrations and shutdown state. Metrics are off in production without `METRICS_TOKEN`. Errors go to a plain JSON webhook instead of a vendor SDK (works with Slack/Teams relays and Sentry-compatible relays); tracing is not built, request ids connect log lines instead. Backups are `pg_dump` custom format with checksums and optional age encryption; a drill restores into a temporary database and verifies the audit chains. Local checks: `scripts/ops/test-backup.sh`, `smoke-container.sh`, `smoke-web.sh`.
- **CI and supply chain**: `ci.yml` runs check (audit, lint, typecheck, tests with Postgres), e2e (including an axe-core accessibility scan, serious/critical fail) and containers (image builds, container smoke tests, backup test, SBOM, Trivy CRITICAL/HIGH). CodeQL, gitleaks (full history, `.gitleaks.toml` allows only placeholder paths) and Dependabot run separately. `pnpm audit` ignores GHSA-vfj7-8cjw-p6xm (braces, dev-only via kysely-codegen, no fix available). GitHub Actions are tagged, not SHA-pinned (not verifiable offline); `docs/REPO-SETTINGS.md` lists the pinning and branch-protection steps the owner must do.
- **Accessibility fixes from the axe scan**: the accent colour is `#d4290f` (was `#ec3013`, contrast below 4.5 on the background); table headers and ghost buttons got stronger text colour; links are underlined; grid headers, PIN dots and the onboarding progress bar got ARIA roles/labels. This is a deliberate small deviation from `design/tokens.css`.
- **Performance**: `PRINCIPAL_CACHE_MS` (default 5000, 0 = off, tests use 0) caches the per-request scope and account-status lookup per process; the trade-off is that a block or role change reaches other requests after at most that time (logout and refresh-token revocation are unaffected). Background jobs moved into `jobs/scheduler.ts`: one process holds advisory lock 7003 per tick, so several API instances do not duplicate jobs; `RUN_JOBS=false` plus `worker.mjs` (compose service `worker`) separates them from HTTP. Web pages are lazy routes. Not built: roster cache (measure first with `scripts/perf/load.js`), off-process PDF/Excel generation.
- **Architecture**: large screens split into `pages/portal|kiosk|admin` folders with barrel files at the old paths (generated mechanically, behaviour unchanged, e2e green); `swaps.ts`, `comms.ts` and `organisation.ts` each gave a second plugin (`openShifts.ts`, `feed.ts`, `organisationDevices.ts`); `myEmployee` moved to `services/collab.ts`. `no-explicit-any` is a warning with a falling cap (`--max-warnings`, now 293) instead of an error, because 260 of them are untyped API reads in the web app; tests are exempt. All row mappers in the API now use table types. Coverage thresholds live in the vitest configs and run in CI. `GET /api/v1/openapi.json` is generated from the zod route schemas (admins only, not public). See `docs/ARCHITECTURE.md`.
- **Privacy** (migration 012: `employee.anonymised_at`, two indexes): anonymisation keeps the statutory working-time records (schedule, punches, absences, contracts, time account) and removes identity: name, birth date (reduced to the year), contact data, badge, PIN, login account (only when no other role or employment uses it), documents, notifications, wishes, availability, questions, calendar feeds, vacation notices; feed author names become "Gelöscht". It is refused for active employees and before contract end + `company.retention_months` (never less than 24 months, ArbZG §16). The daily job `retention` applies it to everybody past that date. The audit log is not rewritten (append-only, hash chained). Reading a person's record (`GET /employees/:id`), exports, document downloads and anonymisation are audited as `personal_data_viewed|personal_data_exported|document_downloaded|employee_anonymised`; views are de-duplicated per reader and person for ten minutes (database time, because audit rows carry real time). Export and anonymise are admin-only (managers cannot); employees can export their own data and see which role kinds looked at it, without names. Documents under `docs/privacy` are templates; the controller completes and signs them.
- **Typed contracts**: response shapes live in `packages/shared` (`dto.ts` by hand, `responses.ts` generated from the demo-seeded API by `scripts/types/gen.mjs`); API mappers are annotated with them; web hooks default to `unknown`; `no-explicit-any` is now an error and the lint warning cap is 0. Typing the web app found a real defect: the candidate finder (`/schedule/candidates?includeBlocked=true`) never sent `blocked`, so blocked people were not disabled in the planning UI. The field is now part of the response and covered by a test. Dates in responses are ISO strings (PIN lock times, last login, device last seen were `Date` objects before and are strings on the wire as before).
- **Measured performance** (see `docs/PERFORMANCE.md`): the load test is `scripts/perf/load.mjs` (autocannon; the earlier k6 file was removed) with p97.5 budgets per scenario, run weekly in CI against a synthetic database. Fixes it drove: race-safe vacation allowance creation, own time zone helpers (`lib/time.ts`, verified equal to date-fns-tz), SQL pre-filter of the Sunday/night history, batched staff list, index `punch_record(schedule_id)` (migration 013), reuse of kiosk reference tokens (valid 5 min, reused while more than 2 min remain), kiosk `last_seen_at` written at most every 30 s. A worker thread for PDF/Excel was measured and not built (about 20 ms per PDF).
- **Test depth**: property-based tests (fast-check) for the rule functions; mutation testing with Stryker on `packages/rules` (score 69.7 % -> 94.9 %, break threshold 90 %, weekly and on rule changes in CI; the first run showed that most helper functions were only exercised through the API vectors, not in the rules package itself); Playwright projects for Firefox and WebKit (`BROWSERS=all`, CI matrix; not run in the sandbox, which only has Chromium). Mutation testing did not find a defect in the rules; it found missing exact tests, now added.
- **Security keys and passkeys (WebAuthn)** (migration 014, `webauthn_credential`): a second factor for staff (superAdmin, admin, manager) next to the authenticator app. Login: after the password, administrators with a key or an app must prove a factor; the 401 answer carries `totpRequired` and, when keys exist, WebAuthn options plus a challenge token (stateless, signed with the `webauthn` key purpose, valid 3 minutes, bound to the user); the client repeats the login with the assertion. `user verification` is "preferred" (a key tap suffices), the RP is `WEB_ORIGIN`, attestation is "none". The signature counter is stored; an assertion with a lower counter is refused. An administrator cannot remove the last factor. Anonymisation deletes the keys. Tested with a software authenticator in the API tests and with Chromium's virtual authenticator end to end. Not built: passwordless login, key attestation checks, a recovery flow other than "another factor or the other administrator resets" (a lost key with no app means an administrator must reset the account through the existing 2FA reset).
- Infrastructure as code: Kustomize base+overlays (no Helm) because there is one app and two environments; web image is nginx-unprivileged on 8080 so the pod can be non-root and read-only; the ops image is Debian (postgres:16) with the node binary copied from node:22-slim so the native argon2 module in the drill matches; deploy verifies cosign signatures before applying; actions are pinned by `scripts/ci/pin-actions.sh` run by the owner because pinning needs read access to other repositories.
- Documentation: manuals are hand-written per language (de/en) because the audience (hotel staff) needs plain task descriptions; the API reference is generated from the route schemas (`pnpm docs:api`) and CI fails when it is stale; relative Markdown links are checked in CI. No screenshots are committed because they go stale with every UI change.
- **Demo seed is independent of the time of day**: the seed no longer clocks in the first still-running shift of the day (that made a different employee "open" depending on the hour and broke e2e tests that clock people in on the tablet, e.g. with `uq_punch_open` or `ALREADY_CLOCKED_IN`). Piotr's unplanned open record is the only open punch; `apps/api/test/seed.test.ts` seeds at every hour of the day and checks that. Reason: tests and demos must be reproducible.
- **Dependabot and pnpm**: Dependabot resolves with a 3-day minimum release age, and our `nodemailer` floor (`^10.0.14`) was itself released inside that window, so every npm update failed. `nodemailer` is listed in `minimumReleaseAgeExclude` in `pnpm-workspace.yaml`. The API runtime image has no npm/corepack (only `node` runs there), which also keeps image scans clean.
